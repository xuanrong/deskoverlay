# DeskOverlay

Windows 桌面工作台（Tauri v2 + WebView2）。应用嵌入 Explorer 桌面 WorkerW，使工作台成为「桌面本身」——Win+D 回到工作台，任务栏仍可见。

## 快速开始

环境要求：Rust（含 `cargo` + `tauri-cli`）、Node.js（仅前端开发态静态服务器与校验脚本用）。

```bash
cd src-tauri
cargo tauri dev
```

`beforeDevCommand` 会自动在 1420 端口提供 `frontend/web` 静态资源。前端是**原生 ESM、无打包器**——改完刷新即可，不需要构建步骤。

只想看前端（不进 Tauri 运行时）：

```bash
cd frontend && node serve.js    # 然后访问 http://localhost:1420
```

此时 `window.__TAURI__` 不存在，`js/bus.js` 会自动回退到 Bus 模拟，界面可点但后端命令无效。

## 使用说明

### 快捷键

| 按键 | 行为 |
| --- | --- |
| `Esc` | 关闭当前浮层（帮助层 / 各弹窗）；**不会退出应用** |
| `Ctrl/Cmd + Enter` | 各弹窗内提交（新建待办 / 灵感 / 快捷访问） |

### 禅道看板

首页卡片显示四个数字，弹窗里直接摊开各自的明细（不需要逐条点开）：

| 指标 | 含义 |
| --- | --- |
| 需求 · 未完成 | 指派给我、还没走完的需求 |
| 需求 · 未验证 | 等我验证的需求 |
| Bug · 未完成 | 指派给我、还没动手修的 Bug |
| Bug · 未验证 | 等我验证的 Bug |

数字为 `—` 表示还没抓取到数据（或未配置），`0` 表示查过了确实没有。抓取每 2 小时一轮，卡片上的刷新按钮可手动触发。

**启用方式**：代码里**没有任何**主机名 / 账号 / 密码。把仓库里的配置示例复制到应用数据目录并填入自己的值即可：

```bash
cp ems.config.example.json "$APPDATA/com.deskoverlay.desktop/ems.json"
```

- 改完配置不必重启应用，下一轮抓取会重新读取。
- 配置缺失或不全时抓取静默跳过，卡片显示「—」并给出原因（不会崩，也不会拿假数据冒充）。
- 配置文件不入库，不会被误提交。

### 数据存放

全部落在 `%APPDATA%/com.deskoverlay.desktop/`，**不上传任何服务器**（在线音乐、云盘等功能按你填写的凭据直连对应服务）。

「系统设置 → 备份与恢复」可把设置 / 待办 / 笔记 / 灵感 / 定时任务定义打包为 zip 导出与导入；索引快照、壁纸缓存、云盘授权等可重建或会过期的内容不在备份范围内。

## 常见问题

- **定时任务「跑了但面板里没有实时输出 / 历史」**：该任务是走「系统计划任务」引擎触发的（`schtasks`）。它由 Windows 拉起、不经过本进程，所以拿不到实时流，只能在面板里读日志文件。要实时输出与历史就改用「面板内调度」（要求应用正在运行）。同一任务同时开两个引擎 = 同一时刻触发两次，编辑器里有明确提示。
- **签到（WorkBuddy / Trae）读不到登录态**：签到链路是「读本地客户端登录态 → 前端 WebCrypto 解密 → 调官方接口」，要求对应客户端已在本机登录过。
- **禅道卡片一直显示「—」**：检查 `%APPDATA%/com.deskoverlay.desktop/ems.json` 是否存在且字段齐全，以及当前网络能否访问 EMS 主机。
- **`cargo check` 有 warning**：本项目基线是 0 warning，warning 视为失败。
